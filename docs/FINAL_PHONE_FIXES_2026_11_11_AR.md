## 2. ملفات الكود والإعداد والموارد

- `app/src/main/java/com/spinel/melkit/ui/SharedControls.kt`: قياس النص وتوزيع الأزرار وارتفاعاتها.
- `ui/MelKitApp.kt`: بطاقة Shizuku، ضمن مجلد Java أعلاه.
- `ui/LibraryScreen.kt`: زر التنظيم، تنبيه الاتصال، إزالة عناصر جذر المكتبة الزائدة.

- `ui/OperationHistoryScreen.kt`: توزيع أقسام الاستعادة الثلاثة.
- `ui/SavedCopiesScreen.kt` و`ui/SavedBundleCard.kt`: تسمية حذف الملف فقط.
- `app/src/main/res/values/strings.xml` و`values-ar/strings.xml`: التسميتان العربيتان والإنجليزيتان.
- `app/src/main/AndroidManifest.xml`: مرجع الأيقونة وroundIcon فقط.
- `app/src/main/res/mipmap-{ldpi,mdpi,hdpi,xhdpi,xxhdpi,xxxhdpi}/`: ملفات الأيقونات.
- `app/src/main/res/mipmap-anydpi-v26/`: تعريفا الأيقونة المتكيفة.
- `app/src/main/res/values/launcher_icon.xml`: خلفية مشتقة من لون زاوية الصورة الأصلية.
- حذف `app/src/main/res/drawable/ic_melkit.xml` القديم غير المستعمل.
- `ci/generate-launcher-icons.py`: إعادة تحجيم وتوسيط الأصل فقط، باستخدام Pillow، دون توليد تصميم بديل.
- `ci/ad-mode.sh` و`ci/build-android.sh` و`app/build.gradle.kts`: اختيار وضع الإعلانات وحاجز منع AAB تجريبي.
- `.gitlab-ci.yml`: إضافة فحص صياغة سكربت وضع الإعلانات، دون تشغيله أو تشغيل Pipeline الآن.
- `README.md` و`docs/ADS_SETUP.md` وهذا التقرير: توثيق النتيجة والإعدادات.

## 3. دمج الأيقونة

| الكثافة | Launcher وRound | طبقة Adaptive |
| --- | --- | --- |
| ldpi | 36×36 | 81×81 |
| mdpi | 48×48 | 108×108 |
| hdpi | 72×72 | 162×162 |
| xhdpi | 96×96 | 216×216 |
| xxhdpi | 144×144 | 324×324 |
| xxxhdpi | 192×192 | 432×432 |

الطبقة الأمامية 108dp، والصورة الأصلية كاملة داخل مربع مركزي 64dp، مع حواف شفافة وخلفية داكنة. لم يُعد رسم الشخصية أو الكتابة أو تغيير ألوانها. روجعت معاينتا القناع الدائري والمربع المستدير؛ الشخصية واسم MelKit ظاهران، وقد يقص قناع المشغّل الزخرفة الطرفية بحسب شكله الطبيعي. نسخة المتجر `artwork/MelKit_Play_Icon_512.png` هي تحجيم كامل للأصل، 32-bit RGBA، بحجم 356,376 بايت، دون إطار جديد أو قص للمحتوى.

المراجع الرسمية: [Adaptive Icon](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive)، [متطلبات صورة المتجر](https://support.google.com/googleplay/android-developer/answer/9866151).

تغيير مرجع Manifest مع الحفاظ على هوية الحزمة يسمح بتحديث الأيقونة عند التثبيت فوق النسخة الحالية. تحقق تحديث ذاكرة المشغّل وسلوكه على الجهاز الحقيقي مؤجل؛ لا طلب لإزالة التطبيق أو مسح بياناته. وضع الأيقونات الملوّنة أو الملوّنة بثيم النظام يبقى قرار Android والمشغّل وإعداد المستخدم.

## 5. أوضاع AdMob في GitLab CI

| المطلوب لاحقًا | BUILD_AAB | MELKIT_LIVE_ADS | النتيجة |
| --- | --- | --- | --- |
| Debug | أي قيمة | أي قيمة | اختبار دائمًا؛ حظر توزيعه بالمفتاح المؤقت باقٍ |
| APK اختبار موقّع بالأصل | false | false أو غير محدد | إعلانات Google التجريبية |
| APK إنتاج | false | true | معرفات MelKit الحقيقية |
| APK وAAB للنشر | true | true أو غير محدد | معرفات MelKit الحقيقية |
| AAB مع إعلانات اختبار | true | false | مرفوض قبل التوقيع أو تنزيل أدوات البناء؛ ومرفوض أيضًا في bundleRelease |

عند الإذن بالبناء لاحقًا: GitLab → Build → Pipelines → Run pipeline → Variables، ثم تحديد القيم المناسبة من الجدول. لا تشغيل الآن. APK الاختبار مبني بنوع Release ليستعمل المفتاح الدائم ويثبت فوق السابق؛ كلمة Release وحدها لا تعني تشغيل الإنتاج، فالمتغير هو المحدد.

المعرفات المراجعة:

- التطبيق: `ca-app-pub-9118481973136364~9451461448`
- البيني: `ca-app-pub-9118481973136364/5379133301`
- فتح التطبيق: `ca-app-pub-9118481973136364/5512216436`

وضع النشر يضبط `BuildConfig.TEST_ADS=false` فيختار المعرفين الحقيقيين. معرفات Google التجريبية باقية لمسار الاختبار فقط. لا تغيير لفاصل 50 ثانية، أو 3 بينيات/5 دقائق، أو شرط التفاعلين، أو UMP، أو حظر الإعلانات أثناء النقل والعمليات الحساسة. لم تُجرَ طلبات أو نقرات إنتاج لاختبار هذه الدفعة.

## 8. اختبار الهاتف بعد البناء

1. تثبيت فوق الحالي بالمفتاح الأصلي، والتأكد من الأيقونة الجديدة في الشاشة الرئيسية وقائمة التطبيقات والإعدادات، مع بقاء البيانات.
2. فحص العربية والإنجليزية على عرض صغير وحجم خط عادي ثم 150% و200%، خصوصًا بطاقة Shizuku قبل الاتصال وبعده.
3. فتح زر التصنيفات من جذر المكتبة ومن الأنواع الأربعة، والتحقق من غياب التذييل الزائد في الجذر وبقاء التنقل بين صفحات الملفات الحقيقية.
4. إنشاء ملف نسخ تجريبي وحذفه بعد التأكيد، والتأكد من تسمية حذف الملف وبقاء النسخ الأخرى.
5. تشغيل الفيديو في اللغتين، والتأكد من ظهور التسمية الجديدة واختيار فيديو اللغة المناسبة.
6. تجربة الأساسية والتراجع والمجموعات كما كانت، والفحص مع صفر تحديد ثم ملف محدد، وبقاء الإحصائيات أسفل الأزرار.
7. تجربة أقسام الاستعادة الثلاثة والتبديل بينها، وفحص عدم حجب الأزرار بشريط التنقل السفلي.
8. بدء الجولة بإعلانات اختبار فقط؛ بعد الانتهاء يمكن بناء النشر بقيم الإنتاج والتحقق المحدود من الإعداد، دون اختبارات ظهور أو نقر متكررة.
